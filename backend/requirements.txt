# Vector Database
#
# ACCEPTED RISK -- every published chromadb is affected; 1.5.9 is the latest on PyPI, so
# there is no upgrade path. The pin is deliberate. Each ID below is also an --ignore-vuln in
# .github/workflows/ci.yml (pip-audit step); keep the two lists identical.
#
#   GHSA-2wm9-hf6c-p5cr, GHSA-xph7-9rjv-w5fr -- cross-tenant authorization bypasses. Not
#     applicable: no Chroma auth is configured and there is one tenant.
#   GHSA-f4j7-r4q5-qw2c (critical, pre-auth code injection) and GHSA-36p7-vc44-83pf (RCE via
#     trust_remote_code on collection modify) -- accepted. With no auth, any caller that can
#     reach chroma:8000 can attempt these.
#
# Who can reach it: chroma publishes no port, but it shares geetanjali-network with nginx,
# backend, worker, Prometheus and Grafana -- and Grafana is internet-facing behind login. That
# is one SSRF hop from the internet, not "post-compromise only". Mitigation planned for
# v1.43.0: chroma on its own internal network with only the services that query it. The
# container already runs non-root, cap_drop: ALL, no-new-privileges.
#
# Client-side tripwire: the client will build a SentenceTransformer embedding function from
# server-returned config (trust_remote_code included) unless we pass our own. Every
# get_or_create_collection call in services/vector_store.py must pass embedding_function.
#
# Re-check PyPI for a patched release; do not assume this is still the best available state.
